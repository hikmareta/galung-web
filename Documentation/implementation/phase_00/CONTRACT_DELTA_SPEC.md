# Proposed Contract Delta Specification — Phase 00

**Status:** review draft; none of these changes is applied to canonical SQL/OpenAPI. Baselines: `database/001_core_schema.sql`, `galung_api_v1/openapi.yaml` v1.0.0, `galung_licensing_v1/LICENSING_PROTOCOL_SPECIFICATION.md` v1.0. Identifiers D-01–D-06 are review packages, not migration IDs. Field types below are proposals requiring PostgreSQL 16/Prisma compatibility, Windows interoperability and owner approval. No production defaults for commercial values.

## D-01 — Identity, authorization and consent (CR-01/11/13; ALIGN-01/09)

**SQL delta proposal:** Keep `users`, `roles`, `permissions`, `auth_sessions`. Add provider-compatible `auth_factors(id uuid PK,user_id FK,kind text,secret_ciphertext bytea NULL,public_credential jsonb NULL,status,created_at,verified_at)`, `auth_recovery_codes(id uuid PK,user_id FK,code_hash bytea UNIQUE,used_at)`, and `auth_challenges(id uuid PK,user_id FK,purpose,challenge_hash,expires_at,consumed_at,attempts)`. Add `legal_acceptances(id uuid PK,user_id FK,terms_version,terms_content_hash,privacy_notice_version,privacy_notice_hash,locale,country_code,accepted_at,request_id,source_order_id FK NULL)` and separate purpose-specific marketing consent records if used. Acceptance of terms, acknowledgment of a privacy notice and optional marketing consent must not be conflated. Provider-managed tables may replace auth tables after security review; never store plaintext MFA secrets or reset tokens. Extend `auth_sessions` with `mfa_completed_at`, `auth_level`, `last_step_up_at`; add indexed expiry/revocation queries. Staff role assignment must create append-only audit events. The exact applicable terms/privacy versions and text digests must be snapshotted on order creation; legal basis and retention require Legal review.

**OpenAPI delta proposal:** `GET /auth/csrf` response `{csrfToken:string,expiresAt:date-time}` under session cookie; `POST /auth/mfa/enroll`, `/auth/mfa/verify`, `/auth/mfa/recovery`, `/auth/step-up`; `GET /me/sessions`, `POST /me/sessions/{id}/revoke`; profile edit and legal consent retrieval. Define per-operation `cookieAuth`, CSRF header, MFA/step-up requirement extension, permission and ownership in description plus `401/403/404/409/422/429` error cases. `POST /orders` requires accepted legal versions that exist server-side. **Decision open:** identity provider, MFA factor and recovery policy, CSRF token strategy/rotation.

**Verification:** AUTH-001–008, API AUTH-01–03/ACL-01–02; cross-account object lookup must not disclose data. Rollout: additive tables, backfill only proven consent records; existing customers must re-consent when legally required, never fabricate acceptance.

## D-02 — Money, bank, invoice and finance (CR-09/10/11/13/14; ALIGN-05/06/08/09/14/17)

**SQL delta proposal:** Add `currency_metadata(code char(3) PK,minor_exponent smallint,valid_from,valid_to,approved_by)` and `bank_account_currencies(bank_account_id FK,currency_code FK,can_receive boolean,PRIMARY KEY(...))`; do not infer currency support from country. Preserve current one-credit-one-approved-review unique index until a split allocation policy is approved. If splits/combined remittances are approved, add `bank_credit_allocations(id,bank_credit_id FK,order_id FK,allocated_minor,currency_code,approved_by,created_at,UNIQUE(bank_credit_id,order_id))` with transactional sum <= actual credited amount and explicit currency conversion/adjustment entries; never silently convert. Add append-only `financial_adjustments`/`payment_reversals` tied to source credit/order, reason, maker/checker and audit; policy pending. Add exclusion or serializable publish guard for non-overlapping `prices` and `plan_policy_versions` intervals. Add `invoices.company_identity_snapshot`, `tax_basis_snapshot`, `payment_terms_snapshot`, and source legal consent FK; retain historical `bank_instructions_snapshot`. Extend `bank_account_change_requests` with immutable proposal digest, requester MFA timestamp, reviewer MFA timestamp, published_by/at, effective_at, old/new version; require requester != reviewer with DB check and service transition. Do not allow direct publication via generic update.

**OpenAPI delta proposal:** `POST /admin/bank-account-change-requests` (proposal; `bank.change.request`), `GET /admin/bank-account-change-requests/{id}`, `POST .../{id}/approve-and-publish` (`bank.change.approve`, independent actor + step-up, atomic publication of exact approved proposal digest/version), `GET /admin/payment-submissions/{id}` with redacted invoice/credit matching, and `GET /admin/license-issuance/{id}`. `BankChangeProposal` requires beneficiary, bank identifiers, supported currencies, reason, expected version; no plaintext account number in ordinary responses. `BankChangeApproval` requires proposal ID, expected state/digest, reviewer rationale and fresh MFA step-up; `409` for self-approval or stale revision. The requester and approver must be different authorized users, each MFA-verified; service and database transaction reject bypass. `ReviewInput` approval must require `bankCreditId` in an approval-specific schema (currently optional generic field); API returns distinct `order.status` and `paymentSummary.status`. Define `PAYMENT_FUNDS_NOT_VERIFIED`, `PAYMENT_AMOUNT_MISMATCH`, `DUPLICATE_BANK_CREDIT`, `BANK_CHANGE_SELF_APPROVAL`, `BANK_CHANGE_STALE_REVISION` stable errors. **Approved principle from Product Owner, 2026-10-18:** beneficiary changes require two different people with MFA. Exact role assignment and emergency recovery policy remain open.

**Verification:** PAY-001–015, CHK-005–009, ADM-003/004, GLG-PAY-001–005; race and credit reuse tests against actual PostgreSQL. Rollout: keep current `bank_accounts` immutable once issued; new change API can publish only after historical invoice snapshots verified. Finance/legal currency, FX, fee, tax, refund and underpayment values remain TBD and block affected checkout/approval features.

## D-03 — Entitlement readiness, periods and license renewal (CR-06/08; ALIGN-04/11)

**SQL delta proposal:** Add append-only `entitlement_events(id uuid PK,subscription_id FK,source_order_id FK,license_id FK NULL,event_type,occurred_at,actor_id FK NULL,request_id,metadata_redacted,UNIQUE(source_order_id,event_type))`. Add `license_revisions(id uuid PK,license_id FK,source_order_id FK UNIQUE,issuance_request_id FK UNIQUE,revision integer,policy_snapshot jsonb,issuance_signing_kid text,issuance_artifact_digest bytea,issuance_artifact_ciphertext bytea,issued_at,issued_by FK,entitlement_ready_at,UNIQUE(license_id,revision))`. Existing `licenses.issuance_request_id UNIQUE` requires expand-and-contract migration: retain old column for old records, backfill revision 1 from verified issuance, then make future linkage via revisions; do not drop until data reconciliation and dual-read sunset. Add `subscription_periods.license_revision_id FK UNIQUE`; enforce no overlapping paid periods per subscription with exclusion constraint or serialized service lock and conflict test. Use `source_order_id UNIQUE` and idempotency to prevent duplicate renewals. Define readiness when the authorized license/entitlement revision and its server-signed issuance artifact are durably committed, claimable by owner and activation can begin; this does **not** require a customer device or device-bound JWS. A device-bound JWS is issued later per activation/validation and has its own `jti` history. The issuance artifact must be privately stored, signed idempotently by issuance-request ID and exposed only to the entitled owner. Freeze its exact serialization and relationship to the desktop grant before implementation. Issuance failure leaves request pending/failed and does not create period. Early renewal starts at previous exclusive paid end when ready before expiry; late starts at `greatest(payment_approved_at,entitlement_ready_at)`. Product decision required for approval-before-expiry/issuance-after-expiry compensation; no default backdating.

**OpenAPI delta proposal:** `LicenseRevision` schema with `licenseId`, `revision`, `sourceOrderId`, `issuedAt`, `entitlementReadyAt`, `policyVersionId`, `status` and no raw secrets. `Issuance` response names logical license and revision and distinguishes `pending`, `failed`, `issued`. `GET /me/subscriptions/{id}` includes authoritative current period, paid/grace exclusive ends and pending renewal state. `POST /admin/license-issuance/{id}/issue` returns canonical revision for identical idempotency key; duplicate conflicting issue returns `409`. Align all UI status paths with frozen OpenAPI names.

**Verification:** SUB-002–005/010–014, LIC-009/014/017, LIC-REN-001–003; clock-controlled leap/month-end and concurrent issuance tests. Migration rollback: retain additive tables and old columns; forward-fix if historic issuance linkage cannot be proven.

## D-04 — Device enrollment, refresh, signed grant and keys (CR-02–07; ALIGN-02/03/10/12)

**SQL delta proposal:** Add `activation_claims(id uuid PK,license_id FK,created_by FK,secret_hash bytea UNIQUE,expires_at,consumed_at,created_at)`, `license_challenges(id uuid PK,license_id FK NULL,activation_id FK NULL,device_key_thumbprint bytea,nonce_hash bytea UNIQUE,expires_at,consumed_at,created_at)`, `license_device_keys(id uuid PK,activation_id FK,public_key_jwk jsonb,thumbprint bytea,algorithm,registered_at,revoked_at,UNIQUE(activation_id,thumbprint))`, `license_refresh_credentials(id uuid PK,activation_id FK,family_id uuid,secret_hash bytea UNIQUE,issued_at,expires_at,consumed_at,rotated_to_id FK NULL,reuse_detected_at,revoked_at)`, `license_token_issuances(id uuid PK,activation_id FK,license_revision_id FK,jti uuid UNIQUE,kid text FK,issued_at,expires_at)`, and `license_signing_keys(kid text PK,algorithm text,public_jwk jsonb,environment,status,published_at,retired_at)`. No private signing key or raw refresh/claim secret in SQL. Extend `license_activations` with current device-key FK, current license revision and offline deadline. Revisit `devices.fingerprint_hash`: optional risk signal, not sole binding. Unique active device-key binding and seat cap require serialized license row lock/transaction; `max_concurrent_sessions` needs a separate lease policy if enforced. A bounded encrypted response cache or equivalent secure recovery mechanism is needed to return the same rotated refresh credential after a lost response, without storing it in plaintext.

**OpenAPI delta proposal:** `POST /me/licenses/{licenseId}/activation-claims` (owner session + step-up; one-time secret response only), `POST /desktop/challenges` (bind challenge to claim or activation, device public-key thumbprint, purpose and short expiry; rate-limit), revise `ActivationRequest` to require license ID, claim secret, challenge ID, device public JWK, canonical signed device proof, client version and idempotency key; revise `ValidationRequest` to require activation ID, challenge ID, current refresh credential and proof. `SignedEntitlementResponse` includes activation ID, compact JWS, server time, offline expiry, **new refresh credential once**, next validation hint. Define crash-safe retry of refresh rotation by idempotency key/body hash and bounded encrypted response cache; old credential reuse outside exact retry revokes family. JWS protected header requires `alg=EdDSA`, `typ=galung-offline+jwt`, pinned `kid`; payload requires `iss`, `aud`, `sub`, `jti`, `iat`, `nbf`, `exp`, activation ID, device thumbprint, product, edition, policy version, entitlement allowlist, paid/effective end, last online validation, offline deadline and license revision. Define exact field names/encoding, algorithm allowlist, strict audience/issuer and key-rotation plan with Desktop Lead. Device PoP algorithm remains pending Windows CNG compatibility review (P-256 candidate). `exp <= min(last_online_validation_at+336h,effective_entitlement_end_at)`; no offline revocation promise.

**Verification:** LIC-DEV/SEC/OFF/KEY/OPS matrices, GLG-LIC-002–007, actual Windows verifier and key rotation. Rollout: desktop protocol version negotiation; old clients cannot silently accept new format; test backwards compatibility or mandate signed update before switch.

## D-05 — Private uploads, CMS, email and releases (CR-12/15; ALIGN-07/13/15/16/18)

**SQL delta proposal:** Extend `file_assets` with upload intent nonce/hash, expected MIME/size/hash, finalized_at, quarantine reason, immutable scan event pointer and retention timestamp; add `file_scan_events(asset_id FK,scanner_version,result,occurred_at)` append-only. Lock order row when allocating `payment_submissions.revision_number`; preserve prior revisions and enforce scanned-clean proof. Add CMS optimistic revision expected version, media rights/consent and portfolio publication metadata; add email dedup key/template locale/status history. Extend `software_releases` with signer identity, signature verification status/time, file hash verification time and publish actor; publish only verified private object.

**OpenAPI delta proposal:** upload intent -> direct private PUT -> explicit `POST /payment-assets/{id}/finalize` verifying object bytes/MIME/hash/size -> scan status -> proof submission. Staff preview only via short-lived authorized ticket after clean scan. Add CMS media/portfolio create/revise/publish/rollback with expected revision and rights fields; release verify/publish/unpublish and authenticated download ticket. Add stable scan, rights and signature failure errors. No real customer files in test fixtures.

**Verification:** PAY-009, WEB-006–009, LIC-020, API UP-01/02/CMS-01–03/REL-01, malware and stale-revision negative tests. Rollout: additive metadata, object cleanup job, private bucket policy and release checks before publication.

## D-06 — Canonical route/error/version manifest (CR-07/13; ALIGN-17)

Freeze reviewed OpenAPI path/DTO set and map every UI dependency (`UI_UX_SCREEN_SPECIFICATION.md` §3) to operation ID. Keep `order.status` distinct from `paymentSummary.status`; never flatten `awaiting_funds` or `amount_mismatch` into order enum. Every mutation must specify auth/permission, ownership, CSRF if cookie-based, idempotency, errors and audit event. Breaking desktop DTO and JWS changes need explicit protocol/API version and Windows compatibility plan; do not silently modify `openapi.yaml`/JSON. Regenerate both exports from reviewed source, validate examples and generated client compatibility before contract freeze.
